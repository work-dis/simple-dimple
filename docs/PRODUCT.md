# Product Vision

## Коротко

`Reality EZPZ` — это очень простой VPN-продукт.

Не "сложная панель управления VPN".

Не "технический кабинет с кучей настроек".

А приложение, которое работает так:

- открыл
- нажал
- подключился

## Продуктовый принцип

Идея в стиле `simple dimple`:

- один главный экран
- одна главная кнопка
- максимум две кнопки
- минимум решений для пользователя

Это значит, что продукт не должен перекладывать на пользователя выбор между `VLESS`, `Trojan`, `Shadowsocks` и другими transport-путями.

Пользовательский опыт должен быть таким:

- нажал `Подключить`
- клиент сам нашел рабочий маршрут
- при деградации тихо переключился на запасной путь

## Основной сценарий

### Экран 1

Пользователь видит:

- текущий статус
- большую кнопку `Подключить`

### Экран 2

Если нужен второй экран, то это один из двух вариантов:

- `Сервер`
- `Аккаунт`

Нельзя одновременно тянуть на главный экран все подряд.

## UX-ограничения

### Можно

- крупная типографика
- очень понятные подписи
- одна доминирующая кнопка
- быстрый доступ к последнему конфигу
- install prompt как нативное приложение

### Нельзя

- 5-6 кнопок на первом экране
- длинные формы
- технические термины для обычного пользователя
- JSON и служебные поля на главном экране
- admin UI в пользовательском сценарии
- ручной выбор протокола как обязательный шаг для подключения

## Пользовательские роли

### Обычный пользователь

Должен видеть:

- подключение
- статус
- сервер
- тариф

### Администратор

Должен иметь:

- отдельный скрытый слой управления
- не мешать обычному сценарию пользователя

## Почему PWA-first

Потому что это дает:

- один UI-код для web/mobile
- быстрый запуск
- простую упаковку в iOS/Android
- installable UX

## Целевой интерфейс

### Home

- статус
- кнопка `Подключить`

### Server

- выбрать сервер, если это вообще нужно пользователю

### Account

- подписка
- Telegram / email
- logout

Текущий прогресс:

- `Home` уже не перегружен выбором сервера
- `Server` вынесен отдельно
- `Account` тоже вынесен в отдельный служебный экран, а не на главный UX-слой
- `Account` уже умеет показывать состояние signed-in / signed-out без усложнения главного сценария

## Ближайший UX-план

В ближайшей разработке мы придерживаемся следующих правил:

1. главный экран должен стать еще проще
2. dashboard-структура должна исчезнуть из пользовательского сценария
3. сложные технические блоки должны быть убраны с поверхности
4. admin-функции должны быть отделены от обычного пользователя

Иными словами:

- сначала простота
- потом расширения
- не наоборот

## Техническая интерпретация продукта

Технически проект может быть сложным внутри:

- Fastify
- Prisma
- Xray
- PostgreSQL
- multi-server
- anti-DPI
- policy engine для выбора маршрута
- несколько transport-профилей и fallback-пути
- независимые server pools по разным провайдерам и ASN

Но снаружи он должен ощущаться очень простым.

Это важное правило проекта:

> Внутри можно быть сложными. Снаружи обязаны быть простыми.

## Как должен думать клиент

Продуктово мы продаем не "один особый протокол", а надежное подключение.

Поэтому клиент должен:

1. сначала пробовать основной маршрут
2. при проблеме быстро переходить на fallback
3. запоминать последний живой путь
4. перепроверять альтернативы без лишнего шума для пользователя

То есть основное обещание продукта звучит так:

> одна кнопка для пользователя, несколько путей внутри системы
